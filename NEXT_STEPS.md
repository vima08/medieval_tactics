## Что работает

- Локальная браузерная игра «Пепел и знамя»: обучение 8×8, основной бой 18×18 против ИИ и hot-seat PvP с отдельным выбором отрядов.
- Детерминированные правила движения, высоты, обзора, боя, отбрасывания и падения; шесть классов с вариантами, модификаторами и артефактами; бюджет набора и готовые составы.
- Предпросмотр действий, угроз и затрат пути; отмена перемещения до атаки; разрушаемые мосты и укрытия; три уровня ИИ.
- Сохранение партии и состава в браузере, локальная статистика, просмотр журнала команд, настройки звука и доступности, анимированные перемещения и процедурный звук.
- Четыре контрольные точки основного поля, оценка после полного раунда, цель — 5 очков с отрывом, предел 12 раундов. Если команда удерживает меньше двух точек, её серия очков сбрасывается; это правило теперь явно показано в интерфейсе.
- Перед основным матчем выбирается одна из трёх целей: контроль точек, поражение командира или уничтожение всего отряда. Выбор сохраняется и воспроизводится. В режимах без контроля сигнальные огни на карте не подсвечиваются. Полученный урон кратко показывается числом над бойцом, включая повтор матча.

## Запуск и проверки

```bash
npm install
npm run dev
npm run build
npm test
```

Откройте адрес Vite, обычно `http://localhost:5173/`. На Windows PowerShell при блокировке `npm.ps1` используйте `npm.cmd` вместо `npm`. Для автоматизации браузера при работающем dev-сервере:

```bash
node scripts/browser-smoke.mjs
node --experimental-strip-types scripts/terrain-browser.mjs
node scripts/pvp-browser.mjs
node --experimental-strip-types scripts/animation-browser.mjs
node scripts/objectives-browser.mjs
```

Последний полный прогон: `npm.cmd run build` успешен; `npm.cmd test` — 7 файлов, **41/41 тест прошёл**. `node scripts/objectives-browser.mjs` проверил все три выбора цели, сохранение в `initial` и кадр урона в повторе без ошибок страницы. Ранее прошли browser smoke, обрушение моста, передача хода в PvP и анимация перемещения. Для браузерных скриптов нужен доступный Chromium Playwright; обычная игра не требует автоматизации.

## Крупнейший оставшийся недостаток

Баланс составов не готов: в независимой серии первый пресет победил второй во всех **8 из 8** проверенных парных сценариев с переменой стороны и сложности. Разведчики не выжили ни в одном из 28 развёртываний серии. Эксперимент с заменами второго пресета дал улучшения лишь в части сценариев и не выявил устойчивого исправления; неподтверждённую замену не внесли. Сравнение 40 сохранённых журналов показало, что накопительные очки убрали бы 58 сбросов серий, но не изменили бы исход 8 основных матчей; это контрфактический просмотр прежних команд, а не новые решения ИИ. Новый режим уничтожения отряда проходит полный headless-матч с атаками и может закончиться ничьей по лимиту 12 раундов. Для него ещё нужна балансная серия с разными составами. Вертикальный срез нельзя считать сбалансированным коммерческим релизом.

## Точная следующая итерация Gauntlet Loop

1. Провести новые headless-матчи с ИИ, который знает о накопительном счёте, и сравнить с действующей серией; архивный контрфактический просмотр есть в `workbench/scoring-study.md`. Оценить длительность, камбэки и боевые столкновения перед сменой правила.
2. Изолировать причину превосходства первого пресета: повторить 8 парных сценариев с зеркальной сменой сторон, точечно менять состав второго пресета или оценку ИИ, фиксировать выбор и выживаемость разведчика. Дополнительно проверить новые цели `commander` и `elimination` в нескольких составах и сложностях. Внести только подтверждённое изменение.
3. Сыграть полный браузерный матч каждой цели против ИИ и в PvP, проверить точность предпросмотра, цифры урона, исходы по лимиту и экран завершения; затем провести независимую проверку тактики, визуала и первого запуска. Сохранить новые кадры и отчёты в `workbench/`.

Дополнительная визуальная полировка нужна после баланса: свежий visual critic ещё не оценивал последние пронумерованные маркеры соседних целей. Полные 15–30 минут реального матча и коммерческий уровень качества не доказаны.
